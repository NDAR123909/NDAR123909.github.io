Quantifying the effect of training-sample range, density, and position on bifurcation extrapolation in a parameter-aware echo state network

Noah D. Riego, sole author. Manuscript in preparation for the Journal of Undergraduate Research in Physics and Astronomy.
Code, data, and figures on GitHub

If a neural network learns the Lorenz system at only a few values of its parameter ρ, how far past those values can it still reproduce the right behavior? I held the network and the amount of training data fixed and changed three things about the training set: how wide a range of ρ it covers, how many values of ρ it samples, and where it sits relative to a bifurcation.

The short version

  • How far the network reaches depends on where the edge of the training window sits, not on how densely the window is filled.
  • Past three samples, adding more stops helping. Reach stays at 0.30 in ρ from 3 samples up to 21.
  • Widening the window raises the highest ρ the network gets right, from 31.2 to 35.5, but the distance it reaches past its own edge goes down and then back up.
  • Wherever I placed the window, the network predicted the chaotic attractor would collapse at ρ = 24.10. The true Hopf bifurcation is at 24.74. The predicted point sits instead near 24.06, where the chaotic attractor itself stops existing.

Background

The Lorenz system

The Lorenz equations are a three-variable model that turns chaotic for some parameter values:

ẋ = σ(y − x),  ẏ = x(ρ − z) − y,  ż = xy − βz

I kept σ = 10 and β = 8/3 at their standard values and varied only ρ. Two values of ρ matter throughout. At ρ ≈ 24.74 there is a subcritical Hopf bifurcation. At ρ ≈ 24.06, the coexistence onset, the chaotic attractor ends. Between the two values, the chaotic attractor and a pair of stable fixed points coexist, so which one a trajectory ends up on depends on where it starts. For that reason I placed every training window above the Hopf point.

Echo state networks

An echo state network is a type of reservoir computer: a large recurrent network whose internal weights are random and never trained. Only a linear readout on top is fit to data, which makes training cheap. The parameter-aware version, from Kong et al., adds one more input that carries the value of ρ. That extra channel is what lets a network trained in one regime say something about regimes it never saw.

The reservoir state r updates as

r(t + Δt) = (1 − α) r(t) + α tanh[Wr r(t) + Win u(t) + b]

where Wr is a fixed sparse random matrix, α is the leak rate, and the input u holds the three standardized Lorenz coordinates plus ρ, scaled separately. The readout is ridge regression, solved in closed form:

Wout = YR⊤(RR⊤ + λI)−1

Here R collects the reservoir states over the training set and Y the one-step-ahead targets. The network has 500 nodes, mean in-degree 6, spectral radius 0.6, α = 1.0, state scaling 0.10, parameter scaling 0.1, bias 0.10, ridge parameter 10−6, and a 1000-step washout. None of these change between experiments.

Cold runs and how reach is measured

To test the network at a value of ρ it never trained on, I give it that ρ and a short primer from the nearest training value, then let it run freely on its own output. It never sees a true trajectory at the target ρ. I call this a cold run.

A cold run is scored by its valid prediction time: how long, in Lyapunov times, before the normalized error first passes 0.4. To get the extrapolation distance Δρ, I step outward from the edge of the training window in increments of 0.1 and find the longest unbroken stretch where the network stays acceptable. Inside the chaotic band, acceptable means a valid prediction time at least half of its in-window value, with the regime still labeled chaotic. Across the Hopf point, only whether the predicted regime matches the true one counts.

Two numbers come out of this. Marginal reach is Δρ itself. Absolute ceiling is the largest ρ reconstructed correctly. Each configuration was run on 32 random reservoirs, and I report medians with bootstrap interquartile bands. Total training length is fixed at 120,000 steps, so when the number of samples changes, the length per sample adjusts. Any change in reach comes from how the data is arranged, not how much of it there is.

Results

The attractor at values the network never saw

Reproducing the bifurcation diagram

First I checked that the setup reproduces the published parameter-aware result. I trained on ρ ∈ {24.56, 26.06, 27.56, 29.06} and ran cold across ρ ∈ [24, 32].

Amplitude is scored only above the Hopf point. Below it, the two attractors coexist, so the single-initial-condition ground truth jumps between the chaotic and fixed-point branches from one ρ to the next while the network stays on the chaotic branch. Over the full grid the error is 7.61%, and nearly all of it comes from eight such points.

Range width

Keeping one sample per unit of ρ and centering the window at ρ = 29, I widened the training range from 2 units to 10. Marginal reach did not grow with width. It fell from 1.20 at width 2 to 0.20 at width 8, then rose to 1.50 at width 10. Over the same sweep the absolute ceiling climbed steadily from 31.2 to 35.5.

My reading of the drop is that as the upper edge moves into more strongly chaotic territory, error grows faster and fewer outward steps clear the bar. I don't have a mechanism for the rise at width 10. Repeating that run with the lowest sample clamped to the Hopf point returned the same 1.50, so it is not an artifact of the grid.

Sample density

With the window fixed at ρ ∈ [26, 32], I increased the number of samples inside it from 2 to 21. From 3 samples on, reach sat at 0.30 for every count, with a degenerate band. The 2-sample case is higher, at 0.80, but that comes from the arrangement: with samples only at the two ends, the in-window reference point falls where the network interpolates poorly. Its valid prediction time drops to 2.34, against 7.6 elsewhere, which lowers the bar for outward steps. It isn't data starvation either. At 21 samples, each segment is still about 85 Lyapunov times long after washout.

Window position

Last, I fixed the window at 4 units wide with 5 samples and slid it so its lower edge sat 0.26, 2.26, 4.26, and 6.26 above the Hopf point. By the strict measure, no window reached across the Hopf point: the depth at which the predicted regime still matched the truth was zero at every position.

Zero depth hides what the network did do. Every window placed the collapse at ρ = 24.10, 0.64 below the true Hopf point, and position made no difference at all. That value is not near the Hopf point at 24.74, where the fixed points become stable. It is near the coexistence onset at 24.06, where the chaotic attractor itself ends. A network that has learned the chaotic attractor follows it down until the attractor really does stop existing. A trajectory already on that attractor has no reason to leave at 24.74 just because another option opens up there. So the network is reporting the boundary of the object it was trained on, not the Lorenz system's bifurcation. That fits two known properties of trained reservoirs: their learned maps have their own bifurcation structure, with critical points near but not on the target system's, and attractor structure can come from the reservoir's own constraints.

Conclusion

On a fixed data budget, spend it on covering a wider range of ρ rather than filling the same range more densely.

The study has limits: one system, one architecture, one bifurcation. These measurements can't say whether the saturation holds for next-generation reservoir computing or for deep reservoirs.

Reproducibility

The pipeline is deterministic on a pinned Python stack, and every source of randomness traces back to one master seed, so a clean checkout rebuilds every figure bit for bit. The code, the result cells behind each figure, and instructions for rerunning everything are in the repository. The animation above uses the trajectories from the repository's Figure 2 script, saved instead of plotted.
